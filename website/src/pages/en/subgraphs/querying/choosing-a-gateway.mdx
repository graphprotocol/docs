---
title: Choosing a Gateway
description: Every gateway on The Graph Network serves the same published Subgraphs. Learn what changes when you choose a gateway, and how to switch.
---

A gateway receives your GraphQL queries, routes them to Indexers on The Graph Network, and bills you for them. Multiple Gateway Operators serve The Graph Network, and every one of them can serve every published Subgraph. These docs use The Graph Foundation's Gateway (`gateway.thegraph.com`) in their examples.

## What Stays the Same

- **Your Subgraph:** you publish once, onchain. You don't publish separately for each gateway.
- **IDs:** the same Subgraph ID and Deployment ID identify the Subgraph on every gateway.
- **Queries:** the [GraphQL API](/subgraphs/querying/graphql-api/) is the same, so your queries don't change.

## What Changes

- **Endpoint:** each Gateway Operator has its own endpoint format. For The Graph Foundation's Gateway, it is `https://gateway.thegraph.com/api/<API_KEY>/subgraphs/id/<SUBGRAPH_ID>`.
- **API keys:** each operator issues its own keys. A key from one operator doesn't work with another.
- **Billing:** pricing, free allowances, and payment methods differ by operator.
- **Limits and support:** rate limits, key restrictions, and support channels differ by operator.

For a full comparison checklist and the list of Endorsed Gateway Operators, see [Subgraph Providers](/subgraphs/providers/overview/).

## Switching Gateways

To move an application to another gateway, create an API key with the new operator, then change your endpoint to that operator's format, keeping the same Subgraph ID or Deployment ID. You can run both side by side while you migrate.
