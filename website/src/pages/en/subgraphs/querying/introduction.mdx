This guide shows you how to find a published [Subgraph](/subgraphs/overview/), choose a gateway, get credentials, and send your first query.

## Overview

Querying a Subgraph with The Graph lets you access onchain data in a fast, reliable, and structured way, without running your own indexing infrastructure. You send GraphQL queries to a gateway, which routes them to Indexers on The Graph Network and bills you for them.

## Steps

### Step 1: Find a Subgraph

Every Subgraph published to The Graph Network has a details page in [Graph Explorer](https://thegraph.com/explorer), operated by The Graph Foundation. Search by name, protocol, network, or contract address. The details page shows the Subgraph's ID, its schema, and a playground where you can try queries. See [Using Graph Explorer](/subgraphs/existing-subgraphs/explorer/).

Note the **Subgraph ID**, or the **Deployment ID** if you want to stay on one exact version. Both work with every gateway. See [Subgraph ID vs Deployment ID](/subgraphs/querying/subgraph-id-vs-deployment-id/).

### Step 2: Choose a Gateway

Multiple Gateway Operators serve every published Subgraph. They differ in API keys, pricing, payment methods, and support, but they all serve the same Subgraphs with the same GraphQL API. This guide uses The Graph Foundation's Gateway (`gateway.thegraph.com`), the default throughout these docs.

> [!NOTE] Multiple Gateway Operators serve every published Subgraph, so you can query through any of them without republishing. See [Choosing a Gateway](/subgraphs/querying/choosing-a-gateway/) and [Subgraph Providers](/subgraphs/providers/overview/).

### Step 3: Get Credentials

For The Graph Foundation's Gateway, create an API key on the **API Keys** page in [Subgraph Studio](https://thegraph.com/studio/apikeys/). See [Managing API Keys](/subgraphs/providers/subgraph-studio/managing-api-keys/). Studio includes a free monthly query allowance, and you can pay for more with GRT or credit card. See [Billing](/subgraphs/providers/subgraph-studio/billing/).

If you use another Gateway Operator, get your API key and billing from that operator.

### Step 4: Send a Query

On the Subgraph's details page in Graph Explorer, click **Query** to copy its query URL for The Graph Foundation's Gateway:

![Query Subgraph Button](/img/query-button-screenshot.png)

![Query Subgraph URL](/img/query-url-screenshot.png)

The URL has this format:

```
https://gateway.thegraph.com/api/<API_KEY>/subgraphs/id/<SUBGRAPH_ID>
```

Send a GraphQL query to it with a POST request:

```bash
curl -X POST "https://gateway.thegraph.com/api/<API_KEY>/subgraphs/id/<SUBGRAPH_ID>" \
  -H "Content-Type: application/json" \
  --data '{"query": "{ _meta { block { number } } }"}'
```

See the [Query API](/subgraphs/querying/graphql-api/) for a complete reference on how to query the Subgraph's entities.

## Handling Errors

- If you get 405 errors with a GET request to the query URL, switch to a POST request.
- GraphQL reports query problems in an `errors` array, often with HTTP status `200`, so check for `errors` as well as the status code.
