A Gateway Provider serves queries for Subgraphs published to The Graph Network. Multiple providers serve the network. Published Subgraphs live onchain, so every provider can serve every published Subgraph, and you can change providers without republishing.

## What a Gateway Provider Does

When your application sends a query, the provider's gateway:

1. Checks your API key or other credentials.
2. Selects Indexers that serve the Subgraph and routes the query to them.
3. Pays those Indexers in GRT through GraphTally.
4. Returns the response and bills you on the terms it sets.

Some providers also offer tools beyond querying, such as deployment and staging environments, version management, or tooling for AI agents.

## Choosing a Gateway

The following providers are endorsed by The Graph ecosystem: each meets the [endorsement criteria](/gateways/subgraphs/ecosystem/collaboration/#endorsement-tier) for transparency, conduct, and brand. Each one sets its own pricing, terms, and support. Endorsement does not mean that The Graph ecosystem operates or guarantees a provider's service, but it does signal that those gateways aim to provide transparency about their service.

## Comparing Subgraph Gateways

Your Subgraph, its IDs and your queries work the same way with every Gateway Provider. What differs is how each provider serves them.

### Gateway Provider Standards

| Area | What every Gateway Provider shares |
| :-- | :-- |
| [Subgraph code and tooling](/subgraphs/developing/introduction/) | The same manifest, mappings and [Graph CLI](/subgraphs/developing/creating/install-the-cli/) |
| [Publishing](/subgraphs/developing/deploying-publishing/publishing-a-subgraph/) | One publish to The Graph Network, which every provider can serve |
| [Curation signal](/subgraphs/developing/curating/) | Signal on The Graph Network attracts Indexers for every provider |
| [Subgraph IDs and Deployment IDs](/subgraphs/querying/subgraph-id-vs-deployment-id/) | The same IDs identify your Subgraph with every provider |
| [GraphQL API](/subgraphs/querying/graphql-api/) | The same schema and queries |
| [Indexer transparency](/gateways/subgraphs/supply-side/tracking-qos/) | Each endorsed provider publishes its production changelog, Indexer blocklist and per-Indexer QoS data |

### Gateway Provider Differences

| Area                        | What to look for                                                              |
| :-------------------------- | :---------------------------------------------------------------------------- |
| Networks                    | Whether the provider serves the networks your Subgraphs index                 |
| Endpoint format             | How the endpoint identifies a Subgraph ID or Deployment ID                    |
| API keys and authentication | Restricting a key to domains or Subgraphs, and spending limits                |
| Payment methods             | GRT, credit card, or other methods                                            |
| Pricing                     | The pricing model and any free allowance, on the provider's live pricing page |
| Rate limits                 | Limits per key and what happens when you reach them                           |
| Staging                     | A development endpoint for testing before you publish                         |
| Additional services         | Tools beyond querying that you might need                                     |
| Support                     | Support channels, response times, and a public status page                    |

## Subgraph Studio

[Subgraph Studio](/subgraphs/providers/graph-foundation/subgraph-studio/), operated by The Graph Foundation, is provider-neutral for building Subgraphs. Whichever Gateway Provider you query through, you can use Studio to create a Subgraph, deploy and test versions with a development query URL and indexing logs, manage versions, and publish to The Graph Network. Once published, the Subgraph can be served by every provider.

Only Studio's API keys and billing are tied to one gateway: they work with the Foundation Gateway.

## Switching Gateway Providers

To query through a different provider:

1. Create an account and an API key with the new provider.
2. Change your query endpoint to the new provider's endpoint, using the same Subgraph ID or Deployment ID.
3. Run both endpoints side by side until you are confident, then retire the old key.

You do not need to republish your Subgraph or change its code or queries. API keys work only with the provider that issued them. For example, API keys from Subgraph Studio work only on The Graph Foundation's gateway.

## Run Your Own Gateway

Anyone can run a gateway on The Graph Network, without permission from The Graph Foundation. See the [Subgraph Gateway docs](/gateways/subgraphs/overview/) and [Gateway Collaboration Framework](/gateways/subgraphs/ecosystem/collaboration/).
