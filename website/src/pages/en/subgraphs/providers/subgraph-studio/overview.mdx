[Subgraph Studio](https://thegraph.com/studio/) is a web app, operated by The Graph Foundation, for creating, deploying, and publishing Subgraphs. Any developer can use it, whichever gateway they query through.

## What You Can Do in Subgraph Studio

### Build and Publish Subgraphs

These features work the same way whichever Gateway Operator you query through:

- Create a Subgraph and get the deploy key for the [Graph CLI](/subgraphs/developing/creating/install-the-cli/).
- [Deploy versions](/subgraphs/providers/subgraph-studio/deploying-to-studio/) and test them in the playground, with a development query URL, and with indexing logs.
- Manage versions, including archiving and unarchiving them.
- [Publish](/subgraphs/developing/deploying-publishing/publishing-a-subgraph/) a Subgraph to The Graph Network, add [curation signal](/subgraphs/developing/curating/), update its metadata, and transfer ownership.

### Query Through The Graph Foundation's Gateway

- [Create and manage API keys](/subgraphs/providers/subgraph-studio/managing-api-keys/) for `gateway.thegraph.com`.
- [Pay for queries](/subgraphs/providers/subgraph-studio/billing/) with GRT or credit card.

> [!NOTE] Subgraph Studio API keys and billing apply only to The Graph Foundation's Gateway. If you query through another Gateway Operator, get your API key and billing from that operator. Publishing in Studio does not tie your Subgraph to any gateway. See [Subgraph Providers](/subgraphs/providers/overview/).

## Staging in Subgraph Studio

Each version you deploy to Studio gets a development query URL, which you can use to test the Subgraph in your application before you publish it. Each account can have up to 3 deployed, unpublished Subgraphs, and the development query URL allows up to 3,000 queries per day. For other ways to test a Subgraph before publishing, see [Testing and Staging](/subgraphs/developing/deploying-publishing/testing-and-staging/).
