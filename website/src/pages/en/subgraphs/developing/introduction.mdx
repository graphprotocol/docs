This section covers everything you do to take a Subgraph from code to a published, indexed API on The Graph Network. Each part below summarizes a folder of the Developing docs and links to its pages.

## Subgraph Development Overview

A Subgraph is a custom, open API that extracts data from a blockchain, processes it, and serves it over GraphQL. Every Subgraph follows the same path: create it, test and publish it, add curation signal, and query it through a gateway.

- **New to Subgraphs?** Start with the [Subgraphs overview](/subgraphs/overview/).
- **Want to build one now?** Follow the [Subgraph Quick Start](/subgraphs/quick-start/).
- **Looking for existing Subgraphs?** Search them in [Graph Explorer](/subgraphs/existing-subgraphs/explorer/).
- **Ready to query?** Choose a gateway on [Subgraph Gateway Providers](/subgraphs/providers/overview/).

## Publishing, Curating, and Managing Subgraphs

Check that the Subgraph works, then publish it to The Graph Network so every gateway can serve it. Add curation signal, which is GRT that tells Indexers your Subgraph is worth indexing; without it, Indexers are unlikely to pick it up. Once published, the Subgraph is owned by the wallet that holds its NFT, so you can transfer it to a new owner or delete it when you no longer need it.

## Optimizing Subgraphs

| [Arrays with @derivedFrom](/subgraphs/best-practices/derivedfrom/) | Model one-to-many relationships without arrays that grow |

| [Debug with Subgraph Forking](/subgraphs/best-practices/subgraph-debug-forking/) | Reproduce a failure at block X without syncing to block X |
