Before you [publish](/subgraphs/developing/deploying-publishing/publishing-a-subgraph/) a Subgraph to The Graph Network, check that it indexes without errors and returns the data you expect. Publishing is an onchain transaction, and each new version costs gas, so it pays to catch problems first.

You can use any combination of the options below. None of them is required to publish.

## Unit Tests

[Matchstick](/subgraphs/tooling/unit-testing-framework/) runs unit tests against your mapping handlers, with mocked events and contract calls, in seconds and with no Graph Node. Use it to test handler logic and edge cases as you write them.

## Run Your Subgraph Locally

[Graph Node Dev Mode](/subgraphs/developing/creating/graph-node-dev/) (`gnd`) runs your Subgraph on your own machine against an RPC endpoint, and redeploys it each time you rebuild. You query it at a local endpoint, check its logs, and iterate without deploying anywhere.

## Debug a Failing Subgraph with Forking

If a Subgraph fails at a block deep in its history, [Subgraph forking](/subgraphs/best-practices/subgraph-debug-forking/) lets you reproduce and fix the failure locally, without syncing to that block first.

## Use a Provider's Staging Environment

Some providers index a Subgraph that you deploy to them before it is published, and give you a development endpoint to test it in your application. What each one offers differs, so check the provider's own docs.

- **Subgraph Studio**, operated by The Graph Foundation: deploy a version with `graph deploy`, test it in the playground, check its indexing logs, and query it at a development query URL. See [Deploying to Subgraph Studio](/subgraphs/providers/subgraph-studio/deploying-to-studio/).
- **Other providers:** see [Subgraph Providers](/subgraphs/providers/overview/) for the Gateway Operators that serve The Graph Network and links to their docs.

## Check Your Subgraph Before Publishing

Whichever option you use, check that:

- The Subgraph syncs to the chain head with no indexing errors.
- Queries return the entities you expect, from the start block onward.
- The `startBlock` in your manifest is the block your contract was deployed in.
- The Subgraph indexes a [supported network](/supported-networks/), and uses only [features that Indexers support](https://github.com/graphprotocol/indexer/blob/main/docs/feature-support-matrix.md).

When you are ready, [publish your Subgraph](/subgraphs/developing/deploying-publishing/publishing-a-subgraph/).
