---
title: Use @derivedFrom Instead of Growing Arrays
---

Arrays in your schema slow a Subgraph down as they grow beyond thousands of entries, because Graph Node copies the whole array on every update. Use the `@derivedFrom` directive for one-to-many relationships instead. It prevents large arrays from forming, simplifies handlers, and keeps entities small, which speeds up both indexing and queries.

## How to Use the `@derivedFrom` Directive

Add a `@derivedFrom` directive after the array field in your schema:

```graphql
comments: [Comment!]! @derivedFrom(field: "post")
```

`@derivedFrom` creates efficient one-to-many relationships, enabling an entity to dynamically associate with multiple related entities based on a field in the related entity. This approach removes the need for both sides of the relationship to store duplicate data, making the Subgraph more efficient.

### Example Use Case for `@derivedFrom`

An example of a dynamically growing array is a blogging platform where a “Post” can have many “Comments”.

Start with two entities, `Post` and `Comment`. Without optimization, you might store the comments as an array on the post:

```graphql
type Post @entity {
  id: Bytes!
  title: String!
  content: String!
  comments: [Comment!]!
}

type Comment @entity {
  id: Bytes!
  content: String!
}
```

This array stores the comment references on the `Post` side of the relationship, and the array grows with every new comment.

Here is the optimized version with `@derivedFrom`:

```graphql
type Post @entity {
  id: Bytes!
  title: String!
  content: String!
  comments: [Comment!]! @derivedFrom(field: "post")
}

type Comment @entity {
  id: Bytes!
  content: String!
  post: Post!
}
```

With `@derivedFrom`, the schema stores the relationship only on the `Comment` side, as a single `post` field. The `comments` field on `Post` is computed at query time, so it never grows in storage.

This makes your Subgraph more efficient and gives you three capabilities:

1. Query a `Post` and see all of its comments.
2. Do a reverse lookup: query any `Comment` and see which post it belongs to.
3. Use [derived field loaders](/subgraphs/developing/creating/graph-ts/api/#looking-up-derived-entities) (`loadRelated()`) to read virtual relationships in your mappings. Derived fields are read-only in mappings.
