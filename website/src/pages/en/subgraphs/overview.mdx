## What is a Subgraph?

A Subgraph is a custom, open API that extracts data from a blockchain, processes it, and stores it so it can be easily queried via GraphQL. Subgraphs can be run locally via Graph Node or be published onto The Graph Network for other consumers to query it openly via multiple [Gateway Providers](/subgraphs/providers/overview/).

### Subgraph Capabilities

- **Access Data:** Subgraphs enable the querying and indexing of blockchain data for web3.
- **Build:** Developers can build, deploy, and publish Subgraphs to The Graph Network. To get started, check out the Subgraph developer [Quick Start](/subgraphs/quick-start/).
- **Index & Query:** Once a Subgraph is indexed, anyone can query it. Explore and query all Subgraphs published to the network in [Graph Explorer](https://thegraph.com/explorer).

### Anatomy of a Subgraph

A Subgraph's manifest defines the smart contracts & network that will be indexed, the events from these contracts to pay attention to, and how to map event data to entities that Graph Node stores and allows to query.

The **Subgraph definition** consists of the following files:

- `subgraph.yaml`: Contains the [Subgraph manifest](/subgraphs/developing/creating/subgraph-manifest/)

- `schema.graphql`: A [GraphQL schema](/subgraphs/developing/creating/ql-schema/) defining the data stored and how to query it

- `mapping.ts`: [AssemblyScript Mappings](https://github.com/AssemblyScript/assemblyscript) that translate event data into entities in your schema

To learn more about each Subgraph component, check out [Creating a Subgraph](/subgraphs/developing/creating/starting-your-subgraph/).

## Subgraph Development Lifecycle

![Subgraph Lifecycle](/img/subgraph-lifecycle.png)

Every Subgraph follows the same path: build it, publish it to The Graph Network, and query it through a gateway. Here's a step-by-step breakdown:

1. [Create a Subgraph](/subgraphs/developing/creating/starting-your-subgraph/)
2. [Test and stage the Subgraph](/subgraphs/developing/deploying-publishing/testing-and-staging/)
3. [Publish](/subgraphs/developing/deploying-publishing/publishing-a-subgraph/) and [curate the Subgraph](/subgraphs/developing/curating/#how-much-signal-to-add) on The Graph Network
4. [Query the Subgraph](/subgraphs/querying/introduction/)

### Build Locally

Great Subgraphs start with a local development environment and unit tests. Developers use [Graph CLI](https://github.com/graphprotocol/graph-tooling/tree/main/packages/cli), a command-line interface tool for building and deploying Subgraphs on The Graph. They can also use [Graph TypeScript](/subgraphs/developing/creating/graph-ts/README/) and [Matchstick](/subgraphs/tooling/unit-testing-framework/) to create robust Subgraphs. [Subgraph Skills](/subgraphs/tooling/skills/) also give AI assistants expert knowledge for developing, testing, and deploying Subgraphs.

### Test and Stage

Before you publish, check that your Subgraph indexes without errors and returns the data you expect. You can run it locally with [Graph Node Dev Mode](/subgraphs/developing/creating/graph-node-dev/), or [deploy it to Subgraph Studio](/subgraphs/providers/graph-foundation/subgraph-studio/), operated by The Graph Foundation, which indexes the deployed version and gives you a development query URL. See [Testing and Staging](/subgraphs/developing/deploying-publishing/testing-and-staging/).

### Publish to and Curate on The Graph Network

When you're happy with your Subgraph, you can [publish it](/subgraphs/developing/deploying-publishing/publishing-a-subgraph/) to The Graph Network.

- This is an on-chain action, which registers the Subgraph and makes it discoverable for Gateway Providers, Indexers, and other data consumers.
- Published Subgraphs have a corresponding NFT, which defines the ownership of the Subgraph. You can [transfer the Subgraph's ownership](/subgraphs/developing/managing/transferring-a-subgraph/) by sending the NFT.
- Published Subgraphs have associated metadata, which provides other network participants with useful context and information.

You can publish with the [Graph CLI](/subgraphs/developing/deploying-publishing/publishing-a-subgraph/#publish-from-the-cli) or in [Subgraph Studio](/subgraphs/developing/deploying-publishing/publishing-a-subgraph/#publish-from-subgraph-studio).

Then add curation signal: GRT deposited on a Subgraph to tell Indexers it's worth indexing. Published Subgraphs are unlikely to be picked up by Indexers without it. You can add signal in the same transaction when you publish. Learn [how much signal to add](/subgraphs/developing/curating/#how-much-signal-to-add).

### Querying Subgraphs

Applications query a published Subgraph through a gateway, which routes each query to Indexers and bills you for it. These docs use The Graph Foundation's Gateway (`gateway.thegraph.com`) with API keys and billing in [Subgraph Studio](/subgraphs/providers/graph-foundation/overview/). While Studio can be used to manage your Subgraphs, there are multiple [Subgraph Gateway Providers](/subgraphs/providers/overview/) that serve Subgraph data. You can query through any of them without republishing. Learn more about [querying Subgraphs](/subgraphs/querying/introduction/).

### Updating, Deleting and Transferring Subgraphs

To update your Subgraph with bug fixes or new functionalities, publish a new version, which points the Subgraph to a new deployment on-chain. You can test new versions locally or in [Subgraph Studio](/subgraphs/providers/graph-foundation/subgraph-studio/) before you publish them, regardless of your Gateway Provider.

- If you selected "auto-migrate" when you applied the signal, updating the Subgraph will migrate any signal to the new version and incur the [curation tax](/subgraphs/developing/curating/#curation-costs) on the migrated signal.
- This signal migration should prompt Indexers to start indexing the new version of the Subgraph, so it should soon become available for querying.

If you no longer need a published Subgraph, you can [delete](/subgraphs/developing/managing/deleting-a-subgraph/) or [transfer](/subgraphs/developing/managing/transferring-a-subgraph/) it. When a Subgraph is deleted, [Curators](/subgraphs/developing/curating/) can withdraw their signaled GRT.
